# ROS1 无人机系统集成

## 1. 概述

ROS1 用节点和消息连接传感器、状态估计、规划与控制。无人机系统集成的主线是定义数据接口、统一空间与时间语义，再安排回调和执行流程，使控制端持续获得有效参考。

## 2. 基础与定义

### 2.1 节点与通信

Topic 承载持续数据流，Service 处理请求与响应，Action 表达有反馈和取消的长任务。Launch 组织节点、命名空间、参数和重映射；YAML 保存可审查的运行配置。

### 2.2 坐标与时间

典型坐标关系为 `map → odom → base_link → sensor`。`odom` 强调局部连续性，`map` 提供全局定位参考，重定位可能使后者发生修正。实际系统若只定义 `world`，应记录其原点、轴向和漂移语义。[REP 105](https://github.com/ros-infrastructure/rep/blob/master/rep-0105.rst)

ROS 常用 SI 单位、右手坐标和机体前左上约定；相机光学系另有轴向约定。[REP 103](https://github.com/ros-infrastructure/rep/blob/master/rep-0103.rst)

## 3. 核心原理

### 3.1 数据与变换

若 $T_{WB}(t)$ 表示消息时刻的机体位姿，$T_{BS}$ 表示传感器外参，则 $T_{WS}(t)=T_{WB}(t)T_{BS}$。点云与图像的空间解释使用其采样时刻的位姿；动态 TF 与静态外参分别维护。

消息的 `frame_id` 标记数据语义，实际数值转换由算法或桥接节点完成。发布同一变换的责任应唯一，避免多个节点竞争同一个父子关系。

### 3.2 时间同步

时间对齐可以使用按消息时间查询 TF、插值里程计或 `message_filters` 的精确及近似同步。同步窗口依据传感器频率与运动速度设定；消息频率正常时仍需检查消息年龄和队列积压。

仿真或录包重放使用 `/clock` 时，相关节点采用一致的时间源。跨机器记录时间偏移，计算耗时使用单调时钟。

### 3.3 回调与执行

输入回调完成校验和缓存，推理线程读取完整快照，控制定时器按固定周期发布当前有效参考。长时间推理、文件写入和等待操作放在控制回调之外。多线程 spinner 需要明确共享状态的锁与所有权，锁只覆盖必要数据交换。

## 4. 实现与应用

### 4.1 接口登记

| 数据 | 必须登记 |
|---|---|
| 里程计 | 坐标系、时间、速度所在坐标、协方差 |
| 深度或点云 | 单位、采样时间、外参、无效值 |
| 规划结果 | 起点、有效时域、位置与导数坐标 |
| 控制指令 | 消息类型、单位、频率、失效处理 |
| 系统状态 | 模式、定位有效性、模型和配置版本 |

### 4.2 诊断与重放

<details class="kt-derivation" id="ros1-diagnostics">
<summary>ROS1 诊断命令</summary>

```bash
rosnode list
rostopic list
rostopic info /odom
rostopic hz /odom
rostopic echo -n 1 /odom
rosrun tf tf_echo odom base_link
rosbag info flight.bag
```

Topic 和 frame 名称按实际配置替换。录制时同时保留观测、里程计、TF、规划参考、实际控制输出和系统状态。重放前核对 `/use_sim_time`，避免真实时间与录包时间混用。

</details>

先运行静态输入和单轴变换，再验证带时间戳的完整链路。状态机将初始化、待命、任务执行、停止与故障恢复定义为显式状态，状态转换由有效输入和执行条件触发。

## 5. 分析与总结

节点连通只说明通信建立，接口验证还包括单位、坐标、时间与执行语义。常见故障按“消息类型与名称 → 坐标与单位 → 时间戳与队列 → 回调与计算 → 控制响应”定位。
