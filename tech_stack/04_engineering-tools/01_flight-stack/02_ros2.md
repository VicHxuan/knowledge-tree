# ROS2 无人机通信

## 1. 概述

ROS2 通过节点、执行器和通信中间件组织无人机的数据与控制链。接入时先确定消息和时间语义，再配置服务质量、回调调度与生命周期，使传感器更新和控制指令具有明确的传输行为。

## 2. 基础与定义

### 2.1 通信接口

Topic 提供数据流，Service 提供短请求响应，Action 提供可取消的任务反馈。ROS2 通过 RMW 抽象通信实现，常用 DDS 实现提供发现和服务质量配置。命名空间与 Domain ID 用于组织系统的发现范围，通信权限另行配置。

### 2.2 服务质量

QoS 描述队列历史、深度、可靠性、持久性和时间约束。发布端提供的能力与订阅端要求需要兼容；例如 best-effort 发布端无法满足 reliable 订阅端的可靠性要求。[官方 QoS 说明](https://github.com/ros2/ros2_documentation/blob/humble/source/Concepts/Intermediate/About-Quality-of-Service-Settings.rst)

## 3. 核心原理

### 3.1 数据新鲜度

高频传感器常优先处理较新的样本，队列深度与丢包策略共同决定延迟。控制指令需要稳定的发布频率和有效期。可靠传输提供重传机制，实际端到端时延仍需测量。

| 数据 | 配置重点 |
|---|---|
| 图像、点云、IMU | 更新频率、队列深度、传感器 QoS 兼容性 |
| 静态标定与配置 | 持久性、晚加入订阅者的读取需求 |
| 控制参考 | 时间戳、有效期、发布周期和超时检测 |
| 状态与诊断 | 可靠性、事件保留与记录频率 |

### 3.2 执行器与生命周期

Executor 调度订阅、定时器和服务回调；Callback Group 规定互斥或可重入关系。将阻塞操作与控制定时器分离，并按数据所有权管理并发访问。

Lifecycle Node 将配置、激活、停用和清理显式化。传感器或模型准备完成后再启用控制输出，失效时按系统状态机停用相关功能。

### 3.3 飞控接口

PX4 的 ROS2 接入需匹配飞控版本、消息定义与桥接组件。直接使用 PX4 消息时核查 NED/FRD 与应用坐标系的转换，时间字段和 Offboard 模式信号依照该版本接口设置。[PX4 v1.16 ROS2 指南](https://docs.px4.io/v1.16/en/ros2/user_guide)

## 4. 实现与应用

### 4.1 通信检查

<details class="kt-derivation" id="ros2-diagnostics">
<summary>ROS2 诊断命令</summary>

```bash
ros2 node list
ros2 topic list -t
ros2 topic info /odom --verbose
ros2 topic hz /odom
ros2 interface show nav_msgs/msg/Odometry
ros2 bag info flight_bag
```

先检查消息类型和端点，再检查 QoS 是否兼容。CLI 订阅的 QoS 也需与被测发布者匹配；录包时记录所用 QoS 覆盖配置。

</details>

### 4.2 ROS1 迁移

逐项迁移消息定义、参数、Launch、时间源、TF 和回调，不直接按话题名称推断语义相同。桥接过渡期间固定转换方向，避免双向转发形成回路。用相同录制输入比较迁移前后的坐标、指令与时间序列。

## 5. 分析与总结

ROS2 通信能力由发现、消息、QoS 和执行器共同决定。无人机集成优先验证观测新鲜度和控制周期，再测量通信吞吐。分布式部署分别记录 ROS 发行版、RMW 实现及飞控消息版本。
