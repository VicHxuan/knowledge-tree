# Technical Article Template — 技术文章写作规范

> **适用范围**：Knowledge Tree `tech_stack/` 下所有最底层技术文章，包括理论、算法、论文方法和工程工具教程。  
> **目标**：结构统一、表达简洁、内容可扩展、保留技术细节。  
> **文件角色**：本文件是写作规范与可复制骨架，不作为网站教程发布。

## 一、通用原则

1. **六模块结构**：正文按「概述 → 基础与定义 → 核心原理 → 实现与应用 → 分析与总结 → 关联与参考」组织。
2. **内容优先**：按技术逻辑编排材料，六模块中的三级及以下标题随内容扩展；保留必要的完整推导、代码和实验结果。
3. **一个主题，一篇文章**：标题准确表达主题；KF/EKF 等相互关联的方法可以在同一篇中用三级标题分别介绍。
4. **先定义，后使用**：数学变量、坐标系、输入输出、假设及符号约定集中在「基础与定义」或首次出现处说明。
5. **依据可追溯**：引用论文、官方文档和仓库原始地址；实验结论与推导对应明确来源或复现条件。
6. **保留已有内容**：整理旧文章时，以标题分级、章节移动、段落归类为主；原公式、代码、图片、表格、链接与技术结论原样保留。需要实质修订的内容另行审查。
7. **空缺如实标记**：六个主模块固定。原文没有相应材料时，在该模块写 `> 待补充。`，并在迁移报告中登记；不凭空生成技术事实。

## 二、标题与排版规则

- `tech_stack/` 原件文章使用一个 `# 文章标题`；网站发布层由同步逻辑转换为 Starlight 页面标题，确保最终网页只有一个 H1。
- 六个主模块统一使用 `##`；模块内使用 `###`，复杂推导再使用 `####`。
- 一级模块顺序固定；三级标题名称与数量按主题自由调整。
- 数学采用标准 LaTeX；长公式、矩阵和推导按可读的多行形式排版。
- 代码块注明语言，保留可复现的输入、参数及预期输出；工程工具类教程记录适用环境。
- 插图、表格紧随相关解释；内部链接采用站点稳定 URL 或现有同步系统支持的链接格式。
- 正文中使用完整的术语首次定义，之后统一简称；符号、单位、坐标系保持一致。
- 本规范文件应排除在知识库发布映射和 Starlight 自动生成教程之外。

## 三、标准文章骨架

复制下方代码块至新的 Markdown 文章，替换占位文字；根据文章类型调整三级标题。

```markdown
# 文章标题（中文 / English）

## 1. 概述（Overview）

简要说明是什么、为什么提出、解决什么问题，以及主要应用场景。

## 2. 基础与定义（Foundations）

### 2.1 相关概念与先修知识

定义理解本文所需的基础概念。

### 2.2 问题建模与符号约定

交代输入、输出、变量、维度、坐标系、基本假设及约束条件。

## 3. 核心原理（Core Principles）

### 3.1 核心思想

通过直观解释建立方法整体认识。

### 3.2 关键机制与推导

按逻辑逐步展开模型、数学推导、系统结构或关键机制。

### 3.3 完整流程

给出算法步骤、伪代码、流程图或操作机制。

## 4. 实现与应用（Implementation & Applications）

### 4.1 实现要点

说明关键数据结构、代码、命令、参数或工程注意事项。

### 4.2 示例与验证

给出实际案例、运行过程、结果及解释。

## 5. 分析与总结（Analysis & Summary）

### 5.1 方法分析

整理适用条件、特点、局限性、复杂度、误差来源与常见问题。

### 5.2 核心结论

用简短条目总结读者应掌握的关键知识。

## 6. 关联与参考（Related Topics & References）

### 6.1 相关知识

- **先修知识**：[知识点](对应链接)
- **进阶阅读**：[知识点](对应链接)
- **相关项目**：[项目](对应链接)

### 6.2 参考资料

1. 论文 / 教材：作者、标题、年份及正式链接。
2. 官方文档：名称与链接。
3. 开源实现：项目名称、版本或提交及链接。
```

## 四、不同文章类型的内容映射

| 模块 | 理论与算法（KF / EKF、PPO、MINCO） | 工程工具（ROS、Git、Docker） |
|---|---|---|
| 1. 概述 | 背景、问题与动机 | 工具定位与使用场景 |
| 2. 基础与定义 | 假设、符号、状态模型 | 环境、术语、系统依赖 |
| 3. 核心原理 | 推导、算法、架构与流程 | 工作机制、架构、关键操作原理 |
| 4. 实现与应用 | 伪代码、数值示例、实验 | 安装、配置、命令、验证 |
| 5. 分析与总结 | 稳定性、误差、复杂度与局限 | 故障排查、边界条件、实践总结 |
| 6. 关联与参考 | 前置算法、论文、代码 | 相关工具、官方文档、项目 |

## 五、已有文章重新排版约束

1. **仅改变表达组织**：允许调整标题层级、章节排序、段落位置、列表与表格排版、空行及标点格式。
2. **保护技术内容**：保留算法公式与符号、推导步骤、代码、命令、实验数值、图片路径、引用和原有技术结论。
3. **复合文章保留并列结构**：例如 KF 与 EKF 分别安排为「核心原理」下的子章节，同时完整保留预测、更新及线性化推导。
4. **缺项记录**：对没有足够原文支撑的模块设置一行 `> 待补充。`，在迁移报告列明缺项，后续单独补写。
5. **链接与锚点校验**：调整标题层级后检查目录锚点、跨章节链接和图片链接。
6. **逐篇审阅**：每篇完成后检查公式、代码、图表、引用、主体文字及网站渲染结果。
7. **保留修改可追溯**：在 Git diff 中明确呈现结构变动，实质技术改动单独提交。

## 六、完成标准

- 正文使用一个文章 H1 与六个标准 H2；下级标题层级清晰。
- 既有技术细节完整保留，空缺模块得到明确标记。
- 数学公式、代码块、图表、站内链接与引用可用。
- 在 VS Code Markdown 与 Astro + Starlight 中均能清晰阅读。
- 网站页面标题、目录、搜索及 Edit this page 链接正确。
