# 无人机导航系统部署与验证

## 1. 概述

机载导航沿“传感器 → 状态估计 → 观测构造 → 规划推理 → 轨迹解码 → 控制执行”闭环运行。部署验证以各接口的数值、坐标和时间一致性为基础，再评价真实运动结果。

## 2. 基础与定义

### 2.1 部署契约

| 对象 | 固定内容 |
|---|---|
| 模型 | 权重校验值、输入输出形状、精度、导出版本 |
| 感知 | 单位、量程、外参、时间戳、有效性 |
| 规划 | 起始状态、输出坐标、轨迹时间与候选规则 |
| 控制 | 参考字段、周期、限幅和失效处理 |
| 运行 | 配置版本、软硬件环境、日志与实验标识 |

### 2.2 坐标约定

用 $R_{WC}$ 表示网络参考系 $C$ 到世界系 $W$ 的旋转，原点为 $p_0^W$。相对位置和导数转换为

$$
p^W=p_0^W+R_{WC}p^C,\qquad
v^W=R_{WC}v^C,\qquad a^W=R_{WC}a^C.
$$

该表达用于固定参考系下的轨迹转换。若参考系随时间转动，速度与加速度关系还含旋转导数项。虚拟观测系、物理传感器系和机体系分别定义，平移与旋转各应用一次。

## 3. 核心原理

### 3.1 输入快照与模型推理

观测快照记录传感器采样时间、位姿时间、坐标变换和目标版本。模型输入按训练侧约定预处理；固定输入分别经过训练框架与部署引擎，比较中间特征和最终输出误差。

### 3.2 轨迹安装与控制执行

推理完成后，按项目约定确定轨迹起点与参考时刻，求解并检查实际准备执行的轨迹。控制定时器读取已安装轨迹，在独立周期内求位置、速度与加速度参考。规划计算与控制发布通过短临界区交换状态。

<details class="kt-derivation" id="trajectory-clock">
<summary>轨迹执行时钟</summary>

按墙钟执行时，轨迹参数为 $\tau=t-t_{\mathrm{install}}$，计算抖动会改变每次采样的时间间隔。按固定步长执行时，$\tau_k=k\Delta t_c$，回调延迟会使轨迹进度落后于墙钟。

两种方式分别记录规划时域、执行游标与实际时间。重新安装轨迹时明确游标初始化、起始导数和交接误差；碰撞预测与实际执行需使用一致的时间语义。

</details>

### 3.3 有效性与系统状态

输入过期、定位无效、非有限输出和无可执行轨迹分别产生明确状态。停止、保持或恢复动作按已验证的系统策略执行，并记录触发原因。模型预测质量、几何检查和控制跟踪分别监控。

## 4. 实现与应用

### 4.1 验证阶段

| 阶段 | 检查对象 | 记录 |
|---|---|---|
| 离线固定输入 | 预处理、模型、轨迹边界 | 输入与输出误差 |
| 录包重放 | 感知、坐标、延迟与候选 | 时间序列与可视化 |
| 软件在环 | 飞控接口、模式和控制响应 | 参考与状态日志 |
| 拆桨地面 | 通信、时钟、失效状态 | 触发与恢复证据 |
| 有界飞行 | 实际跟踪与导航能力 | 场景、速度、结果与失败类型 |

### 4.2 机载链路示例

已有本地激光导航工程采用点云与里程计构造虚拟深度观测，经网络生成候选、轨迹求解与检查，再由独立控制定时器输出参考。本文据此提炼接口组织方式；具体安装角度、标定、型号和当前执行配置由项目记录维护。

这一链路的验证重点包括虚拟观测系与机体系的区别、推理前后状态取样、实际安装轨迹的几何检查、控制线程与推理线程的职责。文章不将离线测试结果替代为实飞成绩。

## 5. 分析与总结

部署结果应能追溯到固定模型、配置、标定和执行时序。先验证输入与指令语义，再评价导航表现。发生异常时保留原始观测、有效性状态、规划输出和实际控制参考，以定位误差进入闭环的位置。
