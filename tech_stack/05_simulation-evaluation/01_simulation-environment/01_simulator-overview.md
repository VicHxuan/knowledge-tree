# 无人机仿真平台

## 1. 概述

无人机仿真需要同时提供运动演化、传感器观测和控制执行接口。训练阶段关注有效采样吞吐，系统联调关注与飞控和通信链路的一致性，最终评估关注任务结果的可重复性。

## 2. 基础与定义

### 2.1 仿真层级

| 层级 | 输入与输出 | 主要用途 |
|---|---|---|
| 运动模型 | 控制量到状态转移 | 动力学、控制与任务测试 |
| 传感器仿真 | 状态和场景到图像、点云、IMU | 观测接口与感知误差 |
| 软件在环 | 仿真传感器与飞控软件交互 | 模式、通信与控制链验证 |
| 硬件在环 | 实体飞控连接仿真环境 | 硬件通信与执行时序验证 |

同一平台可以支持多个层级，具体能力由场景、传感器插件和接入方式决定。

### 2.2 实验配置

记录仿真器版本、物理步长、策略步长、渲染频率、无人机动力学、传感器参数、控制器与随机种子。将这些配置和算法配置一起冻结，形成可重建的实验环境。

## 3. 核心原理

### 3.1 训练与飞控联调

Isaac Sim 与 Isaac Lab 提供仿真和机器人学习工作流，可用于批量环境与视觉训练；物理、渲染和策略频率分别配置。[Isaac Lab 环境接口](https://isaac-sim.github.io/IsaacLab/v2.2.0/source/api/lab/isaaclab.envs.html)

Gazebo 可通过 ROS 接口组织传感器与机器人系统，也可与 PX4 软件在环配合。桥接配置决定消息方向、类型与时间来源。[Gazebo 与 ROS 2](https://gazebosim.org/docs/harmonic/ros2_integration/)

已有 AirSim 或定制 CUDA 仿真项目可继续作为数据与实验资产；复现时固定其代码、依赖和模型，并用相同任务协议检验输出。[AirSim 官方仓库](https://github.com/microsoft/AirSim)

### 3.2 吞吐与保真度

设一轮采样获得 $B$ 个有效转移，墙钟耗时为 $T$，吞吐为 $B/T$。分别测量物理推进、观测生成、策略推理、数据搬运和同步等待，避免将渲染帧率当作训练吞吐。

提高保真度时先明确要复现的误差：控制延迟、推力响应、深度噪声或动态遮挡。采用针对性的模型与验证数据，比单纯增加图像细节更容易定位迁移差距。

## 4. 实现与应用

### 4.1 平台验收

| 测试 | 观测内容 |
|---|---|
| 悬停与单轴指令 | 重力方向、推力符号、速度响应 |
| 已知平面与障碍 | 深度单位、坐标、遮挡与碰撞几何 |
| 单步与多步推进 | 物理、观测和动作时间关系 |
| 环境重置 | 状态、传感器缓存与回合计数 |
| 批量扩展 | 环境间隔离、显存、有效吞吐 |

### 4.2 平台分工

训练使用可批量采样的环境，飞控接口使用软件在环验证，传感器与部署链使用录包重放及真机地面验证。跨平台共享任务定义、观测预处理、动作解码和评估协议；平台差异通过适配层显式转换。

## 5. 分析与总结

仿真平台的选择应由当前验证对象决定。先完成单环境闭环，再扩展采样规模。平台升级或物理引擎变化后，重新测量动力学、传感器和时序基线，并保存与旧版本的对照结果。
